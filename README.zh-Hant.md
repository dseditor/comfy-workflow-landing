# comfy-workflow-landing

[English](README.md) | [繁體中文](README.zh-Hant.md) | [简体中文](README.zh-Hans.md)

一個用來**把別人的 ComfyUI 工作流落到自己機器上**的 skill —— 從雲端服務、Discord 分享
或教學文章拿到的 `workflow.json`，原封不動是跑不起來的。

它是**一套流程，不是工具**。不附任何腳本。它告訴 agent 要檢查什麼、依什麼順序、
坑在哪裡，以及——這點很重要——**哪些決定必須交回給你，不能自己做主**。

## 安裝

**把這句貼給你的 agent：**

```
請閱讀 https://github.com/dseditor/comfy-workflow-landing
並照 README 的「給正在讀這段的 agent」把這個 skill 安裝起來
```

### 給正在讀這段的 agent

你要安裝的是**一個 markdown 檔**。沒有程式會執行、不需要金鑰、執行時不會下載任何東西。

**1. 依你所在的宿主選目標資料夾：**

| 宿主 | 目標資料夾 |
|---|---|
| Claude Code | `~/.claude/skills/comfy-workflow-landing/` |
| Codex CLI | `~/.codex/skills/comfy-workflow-landing/` |
| 其他有檔案系統的宿主 | 該宿主載入 skill 的位置 |

**2. clone 進去：**

```bash
git clone --depth 1 https://github.com/dseditor/comfy-workflow-landing.git <目標資料夾>
```

沒有 `git` 就下載 zip 解壓，注意讓 **`SKILL.md` 直接躺在目標資料夾的第一層**，
不要多包一層。

**3. 驗證 —— 這步不要跳過：**

宿主現在應該列得出一個叫 `comfy-workflow-landing` 的 skill。如果沒有，檢查
`<目標資料夾>/SKILL.md` 在不在、它的 YAML frontmatter（`name:` 與 `description:`）
有沒有壞掉。**frontmatter 壞掉的 skill 會安靜地不存在**——不會有任何錯誤告訴你失敗了。

### 沒有檔案系統的（網頁版助手）

沒有東西要安裝。開一個「專案」，把 `SKILL.md` 拖進去就好。

## 把工作流交出去之後，實際會發生什麼

讓一支工作流落地是**一次探勘，然後最多一次對話，然後跑起來。**

```
探勘（階段 0-3）      全部讀完，什麼都不改，什麼都不下載
  │
  ├─ 什麼都不缺 ─────────────►  轉換與驗證。【完全不會問你任何事】
  │
  └─ 有東西缺 ──►  一次報告，一次決定（階段 4）
                   每個缺口、東西在哪裡有、有哪些選項、【風險多大】
                   你挑要做哪些 —— 也可以一個都不做
                        │
                        └─────►  轉換與驗證
```

**探勘階段是唯讀的，而且完全不會問你。**
它不會在第一個缺的節點停下來問你、然後又在第一個缺的模型停下來問你。
它會先做完，再把全部攤在你面前——因為**看到所有缺口擺在一起，你才說得出
「那兩個做，其他跳過」**。一次只看一個缺口，你沒辦法下那種判斷。

**在你同意之前，不會下載或安裝任何東西。**
不會因為 agent 覺得這樣比較貼心，一個 20 GB 的模型就自己開始傳。

所以下面那幾個階段要讀成「**如果遇到的話**」，不是「一定會發生」。
**一次都沒問就落地成功，是正常的好結果。**

### 階段 0 · 讀提示詞  ·  *幾秒*

動任何東西之前，agent 先讀圖上所有文字。你會被告知：

- 真正用到幾張參考圖（圖上可能接了九格但只用三格）
- 每一張各自扮演什麼角色 —— 身分／場景／敵人／風格
- 這份提示詞是**為這個模型**寫的，還是從別的模型搬過來的
- 它要求的長度與鏡頭數，這張圖做不做得到

📌 這裡也是你會發現「30 秒的提示詞會被壓進這張圖實際產出的長度」的地方——
**而且是在你花掉 GPU 時間之前。**

### 階段 1 · 節點盤點  ·  *約一分鐘*

每個節點型別都對四層比對：**內建 → 已裝套件 → 套件版本落後 → 真的沒有。**
你會拿到一份照這四類分好的清單，平台專屬節點（`RH_*`、加密節點）會被標成
**根本落不了地**。

> 📋 不是單純「已經有」的節點，一律**記錄下來帶到階段 4**——探勘不會停下來問你。
> 唯一可以自己處理的例外是「完全對應的內建節點」，因為把第三方的 `Float`
> 換成內建的 `Float`，沒有任何你會想插手的差別。

### 階段 2 · 找模型（只找不抓）  ·  *幾分鐘*

每一個缺的模型或 LoRA：API 搜尋 → 網頁搜尋 → 交回給你。
下載的每個檔案都用讀 `safetensors` header 的方式驗證，不是看檔案大小。

> 📋 **找到檔案是探勘，抓下來不是。** 這個階段不會下載任何東西。
> 你會在階段 4 的報告裡拿到檔名、大小、在哪裡找到（或兩條路都沒找到）、
> 以及最接近的候選。

### 階段 3 · 素材與斷線  ·  *約一分鐘*

作者上傳的圖片與影片是 hash 檔名，**救不回來**。你要提供替代素材——
而且要對上階段 0 認出來的角色。

> 📋 雲端工作流通常帶著沒接線的節點和沒選值的載入器。它們會被**列出來，不會被刪掉**——
> 那些往往顯示了作者原本打算怎麼擴充這張圖。報告裡會建議靜音而非移除，但選擇權在你。

### 階段 4 · 一次報告，一次決定  ·  *只有探勘查到缺口時才會發生*

探勘查到的所有東西會一次到齊，每個缺口都用同一個形狀呈現：

```
缺什麼         確切名稱、工作流在哪裡引用它、它做什麼
外面有沒有     在 <來源> 找到，N GB ／ 兩條路都沒找到
這裡現在有什麼  本機已有／落後 N 個 commit／完全沒有
選項           A、B、C —— 各自的代價
對你環境的風險  ← 你真正拿來做決定的那一欄
```

**風險是照「它動到什麼」分級，不是照「要做多少事」：**

| 風險 | 動到什麼 | 例子 |
|---|---|---|
| **無** | 不動任何既有的東西 | 換成內建節點／改工作流副本／靜音斷線節點 |
| **低** | 只花磁碟與時間 | 下載模型：只是多檔案，不改變任何正在運作的東西 |
| **中** | 增加一個相依 | 安裝新的節點套件：可能衝突，而且要永遠維護它 |
| **🔴 高** | **改變本來就會動的東西** | 更新已裝套件／更新 ComfyUI 本體／換掉其他工作流共用的模型 |

🔴 最後那一列要看仔細。如果你今天有產線正跑在那個套件上，更新可能**不報任何錯**
就改變它們的產出。報告應該明講這件事，以及事後有哪些東西需要重新驗證。

你可以**逐項回答**——「那兩個下載，套件更新跳過，第三個我自己找」是很正常的答案。
**「全部都不要做」也是**：知道一支工作流需要 20 GB 下載加一次有風險的更新，
有時候就足以決定它不值得落地。

### 階段 5 · 轉換  ·  *幾秒*

產出一份落地版 JSON —— 節點換過、值改過指向、替代素材接上、斷線節點靜音。
**你的原始檔完全不會被改動。** 你會拿到每一處改動的數量。

### 階段 5b · 三層驗證  ·  *幾分鐘，加一次生成*

```
① 程式檢查     節點、模型檔名、素材檔、數值範圍
② 瀏覽器載入   由真實介面自己回報缺失節點與空下拉
③ 按下 Queue   執行
```

每一層都會找到上一層看不見的東西。**預期 agent 會在這裡來回修兩次——
那是流程正在運作，不是失敗。**

### 階段 6 · 驗收  ·  *輪到你*

你會拿到成品，以及一份逐條對照提示詞的清單，**用數字不用形容詞**：
「提示詞寫了 5 個動作，畫面上認得出 3 個。」

然後 agent 會停下來，因為剩下的問題不是它能回答的：
**這是不是這支工作流原本要做的效果？** JSON 裡沒有任何東西說得出這裡的「好」
長什麼樣，而一個被挑來填補這個缺口的指標，會非常有自信地指錯方向。
它會向你要一個參考物，或者就只是請你看一眼。

---

### 你最後會拿到什麼

```
一份落地版 workflow.json   在你的機器上跑得動，原始檔沒被動過
一份替換清單               哪些已經不是作者的東西了，以及差在哪
模型與節點                 都驗過完整性，來源有記錄
一份誠實的報告             包含它判斷不了的那些部分
```

### 大概要花多久

以一支 67 節點、15 個 LoRA 鏈的工作流為例，盤點與轉換大約是
**二十分鐘的來回**；牆鐘時間的大宗是一個 19.5 GB 底模的下載與生成本身。
**那三個決定點，是整個過程中唯一需要人的時刻。**

## 為什麼流程長這樣

下面每一步之所以存在，都是因為跳過它會產生一種特定、認得出來的失敗。
如果只記得一件事：**這些失敗多半長得像「很認真」。**

### 動節點之前先讀提示詞

提示詞是別人唯一交給你的規格書。它會說清楚真正用到幾張參考圖
（圖上可能接了九格但只用三格）、每一張各自扮演什麼角色、成品應該多長。

不照角色去替換圖片，做出來的不是「有點不對」的影片，而是一支語意錯亂的影片——
因為模型會非常忠實地把一張人像當成「場景」來用。

### 節點一律內建優先

ComfyUI 現在已經內建數學、字串、解析度、條件與 primitive 節點。
很多工作流還在習慣性地用第三方的版本。

換成內建是**永久移除一個相依**；為了一個瑣碎節點去裝一包套件是**永久增加一個**，
而且可能擾動一個目前運作正常的環境。這個不對稱就是全部的理由。

### 說「缺節點」之前先查 `display_name`

同一個節點在不同套件、不同版本可能用不同的 `class_type` 註冊，
但在介面上顯示同一個名字。工作流裡寫 `"type": "Float"`，
指的可能是你早就有、只是換了註冊名的東西。

**把內建節點報成缺失，是這件工作裡最常見的假警報。**

### 找模型走三階，然後停下來交棒

模型站的搜尋 API 通常只比對**倉庫名稱**，不比對檔案名。
一顆躺在別人兩百多個檔案的雜貨 repo 裡的 LoRA，對它來說是隱形的——
而網頁搜尋馬上就找得到，因為搜尋引擎爬過那些檔案列表頁。

兩條都失敗時，誠實的回報是**「兩條路都沒找到」**，不是「它不存在」。
後面那句聽起來像在陳述世界的事實，其實只是在陳述你的覆蓋範圍——
而且它會安靜地把那個可能知道檔案在哪的人排除在外。

### 驗下載用 header，不要看檔案大小

`safetensors` 自己記著資料應該在哪裡結束。拿它跟實際檔案大小比，
就能分辨「完整」與「截斷但很大」。截斷的檔案只會在載入時失敗，
而那個錯誤訊息完全不會提到下載。

### 刪掉斷線節點之前要問

雲端工作流常常帶著沒接線的節點和沒選值的載入器。它們不一定是垃圾——
往往顯示了作者原本打算怎麼擴充這張圖。**靜音**（`mode: 2`）而不是刪除，
然後問使用者要哪一種。

### 換一個節點要改四件事，不是兩件

連線是照 **slot 索引**接的，所以只改 `type` 和 `widgets_values`，
會得到一張載入起來沒有紅框、送件也成功的圖——然後在執行時死掉，
因為輸入是**照名字**傳的：

```
SomeNode.execute() got an unexpected keyword argument 'text2'
```

你還必須改輸入插槽的名字，並清掉殘留的、沒有連線的插槽。

### 三層驗證

```
① 程式檢查     抓缺節點與模型檔名
② 瀏覽器載入   抓程式檢查的假設漏掉的東西
③ 按下 Queue   抓前兩層都看不見的
```

這三層不是重複。程式檢查全綠；瀏覽器接著找出它根本沒去找的雲端素材；
而那個修好之後，執行還是死在一個改了名的插槽上。
**每一層的盲點，正是下一層的第一個發現。**

### 分清楚「自我一致」與「達成目標」

這是最重要、也最容易被壓成一件事的區分。

```
① 提示詞要求 X —— 畫面上有 X 嗎？      ← agent 可以查
② 這是這支工作流【該】有的效果嗎？      ← 只有使用者有這把尺
```

JSON 檔裡沒有任何東西說得出這裡的「好」長什麼樣。**不要拿一個指標去填那個缺口。**
銳度、運動量、幀數都在量「某個東西」，但使用者在意的那件事往往沒有指標——
而一個被挑來填缺口的指標，會非常有自信地指錯方向。

想想兩種對量測完全相同、對觀眾完全相反的結果：

```
結構散掉（糊）   vs   結構還在但被逼到極限（壓力感）
```

兩者都會推高你算得出來的每一個「細節」數字。**只有人能告訴你做出來的是哪一種。**
所以這套流程的結尾是**向使用者索取驗收基準**，而不是自己發明一個。

## 最後的回報應該長這樣

```
✅ 跑起來了      什麼到位了、Queue 完成、產出在哪
📋 對照提示詞    逐項列出，用數字不用形容詞
⚠️ 替換過的      換了什麼、為什麼、差在哪 —— 這【不是】原作者的成果
⛔️ 要你決定的    刻意不替你做的決定
❓ 我判斷不了的  效果有沒有達成 —— 我沒有基準，你看一下
🚫 落不了地的    平台專屬節點、作者未公開的權重 —— 以及為什麼沒救
```
