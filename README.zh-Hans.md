# comfy-workflow-landing

[English](README.md) | [繁體中文](README.zh-Hant.md) | [简体中文](README.zh-Hans.md)

一个用来**把别人的 ComfyUI 工作流落到自己机器上**的 skill —— 从云端服务、Discord 分享
或教学文章拿到的 `workflow.json`，原封不动是跑不起来的。

它是**一套流程，不是工具**。不附任何脚本。它告诉 agent 要检查什么、依什么顺序、
坑在哪里，以及——这点很重要——**哪些决定必须交回给你，不能自己做主**。

## 安装

**把这句贴给你的 agent：**

```
请阅读 https://github.com/dseditor/comfy-workflow-landing
并照 README 的「给正在读这段的 agent」把这个 skill 安装起来
```

### 给正在读这段的 agent

你要安装的是**一个 markdown 档**。没有程序会运行、不需要密钥、运行时不会下载任何东西。

**1. 依你所在的宿主选目标文件夹：**

| 宿主 | 目标文件夹 |
|---|---|
| Claude Code | `~/.claude/skills/comfy-workflow-landing/` |
| Codex CLI | `~/.codex/skills/comfy-workflow-landing/` |
| 其他有文件系统的宿主 | 该宿主加载 skill 的位置 |

**2. clone 进去：**

```bash
git clone --depth 1 https://github.com/dseditor/comfy-workflow-landing.git <目标文件夹>
```

没有 `git` 就下载 zip 解压，注意让 **`SKILL.md` 直接躺在目标文件夹的第一层**，
不要多包一层。

**3. 验证 —— 这步不要跳过：**

宿主现在应该列得出一个叫 `comfy-workflow-landing` 的 skill。如果没有，检查
`<目标文件夹>/SKILL.md` 在不在、它的 YAML frontmatter（`name:` 与 `description:`）
有没有坏掉。**frontmatter 坏掉的 skill 会安静地不存在**——不会有任何错误告诉你失败了。

### 没有文件系统的（网页版助手）

没有东西要安装。开一个「项目」，把 `SKILL.md` 拖进去就好。

## 把工作流交出去之后，实际会发生什么

让一支工作流落地是**一次探勘，然后最多一次对话，然后跑起来。**

```
探勘（阶段 0-3）      全部读完，什么都不改，什么都不下载
  │
  ├─ 什么都不缺 ─────────────►  转换与验证。【完全不会问你任何事】
  │
  └─ 有东西缺 ──►  一次报告，一次决定（阶段 4）
                   每个缺口、东西在哪里有、有哪些选项、【风险多大】
                   你挑要做哪些 —— 也可以一个都不做
                        │
                        └─────►  转换与验证
```

**探勘阶段是唯读的，而且完全不会问你。**
它不会在第一个缺的节点停下来问你、然后又在第一个缺的模型停下来问你。
它会先做完，再把全部摊在你面前——因为**看到所有缺口摆在一起，你才说得出
「那两个做，其他跳过」**。一次只看一个缺口，你没办法下那种判断。

**在你同意之前，不会下载或安装任何东西。**
不会因为 agent 觉得这样比较贴心，一个 20 GB 的模型就自己开始传。

所以下面那几个阶段要读成「**如果遇到的话**」，不是「一定会发生」。
**一次都没问就落地成功，是正常的好结果。**

### 阶段 0 · 读提示词  ·  *几秒*

动任何东西之前，agent 先读图上所有文本。你会被告知：

- 真正用到几张参考图（图上可能接了九格但只用三格）
- 每一张各自扮演什么角色 —— 身分／场景／敌人／风格
- 这份提示词是**为这个模型**写的，还是从别的模型搬过来的
- 它要求的长度与镜头数，这张图做不做得到

📌 这里也是你会发现「30 秒的提示词会被压进这张图实际产出的长度」的地方——
**而且是在你花掉 GPU 时间之前。**

### 阶段 1 · 节点盘点  ·  *约一分钟*

每个节点类型都对四层比对：**内置 → 已装套件 → 套件版本落后 → 真的没有。**
你会拿到一份照这四类分好的清单，平台专属节点（`RH_*`、加密节点）会被标成
**根本落不了地**。

> 📋 不是单纯「已经有」的节点，一律**记录下来带到阶段 4**——探勘不会停下来问你。
> 唯一可以自己处理的例外是「完全对应的内置节点」，因为把第三方的 `Float`
> 换成内置的 `Float`，没有任何你会想插手的差别。

### 阶段 2 · 找模型（只找不抓）  ·  *几分钟*

每一个缺的模型或 LoRA：API 搜索 → 网页搜索 → 交回给你。
下载的每个文件都用读 `safetensors` header 的方式验证，不是看文件大小。

> 📋 **找到文件是探勘，抓下来不是。** 这个阶段不会下载任何东西。
> 你会在阶段 4 的报告里拿到文件名、大小、在哪里找到（或两条路都没找到）、
> 以及最接近的候选。

### 阶段 3 · 素材与断线  ·  *约一分钟*

作者上传的图片与视频是 hash 文件名，**救不回来**。你要提供替代素材——
而且要对上阶段 0 认出来的角色。

> 📋 云端工作流通常带着没接线的节点和没选值的加载器。它们会被**列出来，不会被删掉**——
> 那些往往显示了作者原本打算怎么扩充这张图。报告里会建议静音而非移除，但选择权在你。

### 阶段 4 · 一次报告，一次决定  ·  *只有探勘查到缺口时才会发生*

探勘查到的所有东西会一次到齐，每个缺口都用同一个形状呈现：

```
缺什么         确切名称、工作流在哪里引用它、它做什么
外面有没有     在 <来源> 找到，N GB ／ 两条路都没找到
这里现在有什么  本机已有／落后 N 个 commit／完全没有
选项           A、B、C —— 各自的代价
对你环境的风险  ← 你真正拿来做决定的那一栏
```

**风险是照「它动到什么」分级，不是照「要做多少事」：**

| 风险 | 动到什么 | 例子 |
|---|---|---|
| **无** | 不动任何既有的东西 | 换成内置节点／改工作流副本／静音断线节点 |
| **低** | 只花磁盘与时间 | 下载模型：只是多文件，不改变任何正在运作的东西 |
| **中** | 增加一个相依 | 安装新的节点套件：可能冲突，而且要永远维护它 |
| **🔴 高** | **改变本来就会动的东西** | 更新已装套件／更新 ComfyUI 本体／换掉其他工作流共用的模型 |

🔴 最后那一列要看仔细。如果你今天有产线正跑在那个套件上，更新可能**不报任何错**
就改变它们的产出。报告应该明讲这件事，以及事后有哪些东西需要重新验证。

你可以**逐项回答**——「那两个下载，套件更新跳过，第三个我自己找」是很正常的答案。
**「全部都不要做」也是**：知道一支工作流需要 20 GB 下载加一次有风险的更新，
有时候就足以决定它不值得落地。

#### 在手机上或终端机里看报告

一份探勘报告每个缺口有四、五栏。**在终端机里会换行换成一团，在手机上更糟。**
所以这份报告也可以输出成**一个自包含的 HTML 档**——不连 CDN、不连网络、脱机就能开，
一个缺口一张卡片，风险同时用颜色和文本标示（只用颜色对色盲用户无效）。

真正有用的是它结尾那个按钮：**「拷贝我的决定」**，
把你的勾选变成一行可以直接贴回对话的文本。

```
[ 拷贝我的决定 ]  →  「unet: 下载最接近的（19.5 GB）
                      package: 这次更新跳过
                      lora_3: 我自己找」
```

没有那个按钮，这个文件只解决了「看」，却把你留在手机键盘上打一整段字。
**纯文本摘要无论如何都会留在对话里**——开文件永远不是回答你的必要条件。

### 阶段 5 · 转换  ·  *几秒*

产出一份落地版 JSON —— 节点换过、值改过指向、替代素材接上、断线节点静音。
**你的源文件完全不会被改动。** 你会拿到每一处改动的数量。

### 阶段 5b · 三层验证  ·  *几分钟，加一次生成*

```
① 程序检查     节点、模型文件名、素材档、数值范围
② 浏览器加载   由真实接口自己回报缺失节点与空下拉
③ 按下 Queue   运行
```

每一层都会找到上一层看不见的东西。**预期 agent 会在这里来回修两次——
那是流程正在运作，不是失败。**

### 阶段 6 · 验收  ·  *轮到你*

你会拿到成品，以及一份逐条对照提示词的清单，**用数字不用形容词**：
「提示词写了 5 个动作，画面上认得出 3 个。」

然后 agent 会停下来，因为剩下的问题不是它能回答的：
**这是不是这支工作流原本要做的效果？** JSON 里没有任何东西说得出这里的「好」
长什么样，而一个被挑来填补这个缺口的指针，会非常有自信地指错方向。
它会向你要一个参考物，或者就只是请你看一眼。

---

### 你最后会拿到什么

```
一份落地版 workflow.json   在你的机器上跑得动，源文件没被动过
一份替换清单               哪些已经不是作者的东西了，以及差在哪
模型与节点                 都验过完整性，来源有记录
一份诚实的报告             包含它判断不了的那些部分
```

### 大概要花多久

以一支 67 节点、15 个 LoRA 链的工作流为例，盘点与转换大约是
**二十分钟的来回**；墙钟时间的大宗是一个 19.5 GB 底模的下载与生成本身。
**那三个决定点，是整个过程中唯一需要人的时刻。**

## 为什么流程长这样

下面每一步之所以存在，都是因为跳过它会产生一种特定、认得出来的失败。
如果只记得一件事：**这些失败多半长得像「很认真」。**

### 动节点之前先读提示词

提示词是别人唯一交给你的规格书。它会说清楚真正用到几张参考图
（图上可能接了九格但只用三格）、每一张各自扮演什么角色、成品应该多长。

不照角色去替换图片，做出来的不是「有点不对」的视频，而是一支语意错乱的视频——
因为模型会非常忠实地把一张人像当成「场景」来用。

### 节点一律内置优先

ComfyUI 现在已经内置数学、字符串、分辨率、条件与 primitive 节点。
很多任务作流还在习惯性地用第三方的版本。

换成内置是**永久移除一个相依**；为了一个琐碎节点去装一包套件是**永久增加一个**，
而且可能扰动一个目前运作正常的环境。这个不对称就是全部的理由。

### 说「缺节点」之前先查 `display_name`

同一个节点在不同套件、不同版本可能用不同的 `class_type` 注册，
但在接口上显示同一个名字。工作流里写 `"type": "Float"`，
指的可能是你早就有、只是换了注册名的东西。

**把内置节点报成缺失，是这件工作里最常见的假警报。**

### 找模型走三阶，然后停下来交棒

模型站的搜索 API 通常只比对**仓库名称**，不比对文件名。
一颗躺在别人两百多个文件的杂货 repo 里的 LoRA，对它来说是隐形的——
而网页搜索马上就找得到，因为搜索引擎爬过那些文件列表页。

两条都失败时，诚实的回报是**「两条路都没找到」**，不是「它不存在」。
后面那句听起来像在陈述世界的事实，其实只是在陈述你的覆盖范围——
而且它会安静地把那个可能知道文件在哪的人排除在外。

### 验下载用 header，不要看文件大小

`safetensors` 自己记着数据应该在哪里结束。拿它跟实际文件大小比，
就能分辨「完整」与「截断但很大」。截断的文件只会在加载时失败，
而那个错误消息完全不会提到下载。

### 删掉断线节点之前要问

云端工作流常常带着没接线的节点和没选值的加载器。它们不一定是垃圾——
往往显示了作者原本打算怎么扩充这张图。**静音**（`mode: 2`）而不是删除，
然后问用户要哪一种。

### 换一个节点要改四件事，不是两件

连接是照 **slot 索引**接的，所以只改 `type` 和 `widgets_values`，
会得到一张加载起来没有红框、送件也成功的图——然后在运行时死掉，
因为输入是**照名字**传的：

```
SomeNode.execute() got an unexpected keyword argument 'text2'
```

你还必须改输入插槽的名字，并清掉残留的、没有连接的插槽。

### 三层验证

```
① 程序检查     抓缺节点与模型文件名
② 浏览器加载   抓程序检查的假设漏掉的东西
③ 按下 Queue   抓前两层都看不见的
```

这三层不是重复。程序检查全绿；浏览器接着找出它根本没去找的云端素材；
而那个修好之后，运行还是死在一个改了名的插槽上。
**每一层的盲点，正是下一层的第一个发现。**

### 分清楚「自我一致」与「达成目标」

这是最重要、也最容易被压成一件事的区分。

```
① 提示词要求 X —— 画面上有 X 吗？      ← agent 可以查
② 这是这支工作流【该】有的效果吗？      ← 只有用户有这把尺
```

JSON 档里没有任何东西说得出这里的「好」长什么样。**不要拿一个指针去填那个缺口。**
锐度、运动量、帧数都在量「某个东西」，但用户在意的那件事往往没有指针——
而一个被挑来填缺口的指针，会非常有自信地指错方向。

想想两种对量测完全相同、对观众完全相反的结果：

```
结构散掉（糊）   vs   结构还在但被逼到极限（压力感）
```

两者都会推高你算得出来的每一个「细节」数字。**只有人能告诉你做出来的是哪一种。**
所以这套流程的结尾是**向用户索取验收基准**，而不是自己发明一个。

## 最后的回报应该长这样

```
✅ 跑起来了      什么到位了、Queue 完成、产出在哪
📋 对照提示词    逐项列出，用数字不用形容词
⚠️ 替换过的      换了什么、为什么、差在哪 —— 这【不是】原作者的成果
⛔️ 要你决定的    刻意不替你做的决定
❓ 我判断不了的  效果有没有达成 —— 我没有基准，你看一下
🚫 落不了地的    平台专属节点、作者未公开的权重 —— 以及为什么没救
```
